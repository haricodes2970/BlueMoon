# ADR-0033: Adopt Render for Production Backend and PostgreSQL Hosting

- **Date:** 2026-08-16
- **Status:** Accepted
- **Supersedes:** [ADR-0012](./ADR-0012-railway.md) (Railway for
  Backend/Database Hosting)

## Context

ADR-0012 chose Railway to host `apps/server` and PostgreSQL. Milestone
1.0's deployment-readiness pass (ADR-0032) built and locally verified
a production Dockerfile and a Railway-specific `railway.json`, but no
external Railway deployment was ever performed (see
`docs/deployment/README.md`'s Milestone 1.0 Completion Criteria). The
platform decision changed to Render before that external deployment
happened — this ADR records that change and what it does and doesn't
affect.

**What does not change:** `apps/web` still deploys to Vercel
(ADR-0013, unaffected). `apps/server`'s production `Dockerfile`
(ADR-0032) is unchanged and directly reused — Render, like Railway,
builds and runs an arbitrary Dockerfile from a repository, so the
three-stage build (filtered install + Turbo build, `--prod`-only
install, minimal `node:20-alpine` runtime) needed no modification.
Neither did `apps/server`'s runtime code: it already binds to all
interfaces (Node's default when no `hostname` is passed to
`server.listen()`), already reads `PORT` from the environment
(`loadServerEnv()`), already handles `SIGTERM` gracefully, and
`/health` already needs no authentication — every one of these was
independently required by Railway too, so nothing about "being
Render-ready" turned out to be Railway-specific application behavior.
Rate limiting, WebSocket hardening (origin validation, heartbeat, max
payload), cookie/CORS configuration, and the WS ticket authentication
model (ADR-0030) are entirely unaffected — none of it encodes any
platform assumption beyond "one trusted reverse proxy hop," which
holds for Render's edge exactly as it held for Railway's.

## Decision

**Use Render** to host `apps/server` (as a Docker-runtime Web Service)
and PostgreSQL (a Render Postgres instance), replacing Railway.

- `railway.json` removed — Render does not read it and leaving it in
  the repository would misleadingly suggest Railway is still the
  target.
- `render.yaml` added at the repository root — a Render Blueprint
  defining the web service (`runtime: docker`, `dockerfilePath:
apps/server/Dockerfile`, `dockerContext: .`, `healthCheckPath:
/health`) and the PostgreSQL database in one file. Chosen because it
  materially improves reproducibility for this specific case: a
  Blueprint's `fromDatabase: {property: connectionString}` wires
  `DATABASE_URL` to Render's _internal_ connection string
  automatically (traffic never leaves Render's private network),
  which the task's explicit requirement to "connect using Render's
  internal database URL" would otherwise require manually copying a
  value between two dashboard screens and keeping in sync by hand.
  `generateValue: true` for `JWT_ACCESS_TOKEN_SECRET` means a
  32-random-byte secret is generated by Render on first deploy and
  never has to be generated, transcribed, or pasted by a human at
  all. `sync: false` for `WEB_ORIGIN` correctly reflects that it's not
  a secret but also isn't knowable until the Vercel deployment exists,
  so it prompts for manual entry in Render's dashboard instead of
  being hardcoded to a placeholder.
- Every code comment referencing "Railway's edge" as the trusted
  single reverse-proxy hop (`getClientIp`'s proxy-trust assumption,
  `env.ts`'s `COOKIE_SAME_SITE` reasoning, `index.ts`'s graceful-
  shutdown comment) updated to say "Render's edge" — the underlying
  assumption (exactly one trusted hop) and the code implementing it
  are unchanged; only which platform's edge that hop refers to
  changed.
- `docs/deployment/README.md` rewritten from Railway to Render
  throughout (topology, environment variable tables, health check,
  rollback, Two Supported Domain Shapes now naming Render's default
  domain `onrender.com` instead of `up.railway.app`).
- ADR-0012 marked **Superseded by ADR-0033** in `DECISIONS.md` and in
  its own Status line — not deleted, not rewritten; it remains an
  accurate record of what was decided in July 2026 and why.
- ADR-0031 and ADR-0032 gained short amendment notes pointing here
  rather than being rewritten — their reasoning (cross-origin cookie
  behavior, proxy trust, choosing Docker over a buildpack for this
  monorepo shape) is unaffected by the platform swap and remains
  correct as written.

## Alternatives Considered

- **Stay on Railway, just deploy for real:** rejected — this ADR
  responds to an explicit platform-change instruction, not a technical
  finding against Railway. Nothing in this repository's Railway
  preparation (Dockerfile, environment contract) turned out to be
  wrong or Railway-specific in a way that would have blocked a real
  Railway deployment; the switch is a platform choice, not a fix.
- **Fly.io, Heroku, or another Docker-friendly PaaS:** not evaluated —
  out of scope for this task, which specified Render explicitly.
- **No Blueprint, dashboard-only Render configuration:** rejected —
  loses the internal-database-URL auto-wiring and the reproducibility
  of having the service topology as a reviewable, version-controlled
  file, for no offsetting benefit over the Blueprint approach.

## Consequences

- `render.yaml` and the updated `docs/deployment/README.md` are the
  new authoritative deployment configuration; `railway.json` is gone.
- No functional/runtime code changed beyond comment text — confirmed
  by an unchanged `pnpm test`/`pnpm test:db` pass count and an
  unchanged `docker build`/`docker run` verification (same Dockerfile,
  same image, same local golden-path result as ADR-0032's
  verification).
- External deployment still has not been performed on any platform —
  this ADR makes the repository Render-ready, it does not itself
  constitute a deployment. See `docs/deployment/README.md`'s
  completion criteria.

## Future Implications

If a second reverse-proxy hop is ever placed in front of Render's edge
(e.g. a CDN), `getClientIp`'s single-trusted-hop assumption needs
revisiting — unchanged from the equivalent note in ADR-0031, just
naming a different platform's edge as the trusted hop.
